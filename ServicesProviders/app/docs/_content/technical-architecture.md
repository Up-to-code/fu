# البنية التقنية (ملاحظات قابلة للتوسع)

## نظرة عامة

يعتمد التطبيق على Next.js (App Router) مع مكونات واجهة مبنية على Radix UI وTailwind، والتحقق من البيانات عبر Zod، وإدارة الحالة على العميل عبر Zustand لتوفير تجربة سريعة وواضحة لمقدم الخدمة.

## الوحدات (حدود منطقية مقترحة)

- **الخدمات**: الكتالوج، النطاق السعري، والخيارات المسعّرة
- **الحجوزات**: الموعد، دورة الحياة، والارتباط بالمحادثة
- **المراسلات**: المحادثات والرسائل والمرفقات
- **المدفوعات**: عمليات الدفع وWebhooks وسياسة الصرف/الضمان
- **الإشعارات**: إنشاء الإشعار وتصنيفه وتسليمه
- **التقييمات**: النجوم والتعليقات والمراجعة/البلاغات
- **المالية**: المحفظة والحساب البنكي وسجل الصرف

## ملكية الحالة (Client/Server)

- يتم استخدام مخازن Zustand على العميل لتجربة واجهة سريعة وبيانات تجريبية.
- يبقى الخادم هو مصدر الحقيقة النهائي عند تفعيل الخلفية، خاصةً في:
  - حالة الحجز والدفع
  - سجل الرسائل والمرفقات
  - أهلية الصرف وسجل العمليات

## سير عمل قائم على الأحداث (خلفية مقترحة)

أحداث موصى بها:

- `booking.created`
- `booking.accepted`
- `payment.confirmed`
- `service.started`
- `service.milestone_updated`
- `service.completion_requested`
- `service.completed`
- `payout.released`

يمكن أن ينتج عن كل حدث:

- إنشاء إشعارات وإرسالها
- تسجيل تدقيق (Audit Log)
- تحديث عدادات التحليلات

## تتبع زمني (Time-Based)

- مؤقتات SLA (مهلة قبول مقدم الخدمة)
- تذكيرات قبل الموعد
- اكتشاف التأخير والتصعيد

## مراجع داخل التطبيق

- لوحة التحكم: `/dashboard`
- الرسائل: `/messages`
- المالية: `/finance`
