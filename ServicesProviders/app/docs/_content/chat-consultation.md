# المراسلات والاستشارة (العميل ↔ مقدم الخدمة)

## الهدف

تعد المراسلات القناة الأساسية لتوضيح المتطلبات وتبادل الملفات وتوثيق الاتفاق على نطاق العمل، إضافةً إلى متابعة التعديلات وإغلاق الخدمة بشكل منظم.

## أين تجدها

- الرسائل: `/messages`

## رحلة الاستخدام

1. عند إنشاء الحجز، يتم إنشاء محادثة مرتبطة به أو ربطه بمحادثة موجودة.
2. يرسل العميل المتطلبات والملفات (صور/مستندات) والتفاصيل اللازمة.
3. يراجع مقدم الخدمة المعلومات ويطرح أسئلة توضيحية عند الحاجة.
4. يتم الاتفاق على نطاق العمل ومعايير التسليم والمدة المتوقعة.
5. يرسل مقدم الخدمة تحديثات مرحلية (مثال: “تم إنجاز المسودة الأولى”).
6. يطلب العميل تعديلات أو يؤكد التقدم.
7. عند اكتمال العمل، يطلب مقدم الخدمة تأكيد الإكمال من العميل.

## إرشادات جودة التواصل

- استخدم لغة واضحة ومباشرة، وحدد المطلوب بدقة (ما الذي سيتغير؟ ومتى؟).
- وثّق أي تغيير في النطاق أو السعر أو الموعد داخل المحادثة.
- عند استلام ملف أو ملاحظة مهمة، أكد الاستلام برسالة قصيرة لتقليل الالتباس.

## متطلبات واجهة المستخدم

- قائمة محادثات + عرض المحادثة
- مؤشر واضح للرسائل غير المقروءة
- تجربة كاملة على الجوال (إخفاء/طي قائمة المحادثات)
- مرفقات مع تحقق من النوع والحجم

## ملاحظات تقنية وتشغيلية

- ترتيب الرسائل يجب أن يكون مستقراً باستخدام (وقت الإنشاء + المعرّف).
- التحديث الفوري يمكن تنفيذه عبر Polling أو WebSockets مع دعم إعادة الاتصال.
- أقل مستوى مطلوب: حالة “مقروء/غير مقروء”.
- أمان المرفقات:
  - التحقق من نوع الملف وحجمه قبل الرفع
  - استخدام روابط رفع موقعة عند اعتماد تخزين خارجي
  - عدم نشر روابط التخزين الخاصة للعامة
